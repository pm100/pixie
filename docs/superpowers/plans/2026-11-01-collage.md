# Collage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the greyed-out Create > Collage placeholder (issue #12) into a working tool: pick a template, page size, gap, corner rounding and background colour, drag each photo to adjust its crop, and save the page as a PNG or JPEG.

**Architecture:** A template is data: a list of cells as fractions of the page, defined once in Rust (`pixie-image::collage`) and sent to the UI. The UI previews with CSS percentages; Rust does the real render from the original files with the `image` crate. Both use one crop rule ("cover" fit with a focus point 0..1), so the preview matches the saved picture. Photos come from the Tools "Working on" selection, as Print does.

**Tech Stack:** Rust (`image` 0.25 already in the workspace), Tauri commands in `src-tauri/src/lib.rs`, Svelte 5 + TypeScript + vitest, `@tauri-apps/plugin-dialog` `save()`.

**Spec:** `docs/superpowers/specs/2026-10-15-pixie-design.md` section 5 ("Collage") and the Create row of `docs/superpowers/specs/2026-10-29-tool-tabs-design.md`. No collage-specific spec exists; the calls marked *(my call)* below are mine, not agreed.

## Global Constraints

- Never commit or push unless the user says so (AGENTS.md). The "Commit" steps below mean: stop and ask, or commit only if told to.
- No compiler warnings: `cargo check --workspace --all-targets` must stay clean; no `#[allow]`; delete dead code.
- Only pluralise when a count is more than one: use `plural` in `ui/src/lib/format.ts`.
- Buttons: `class="primary"` for the one main action (Save collage…); styles are global, no per-component button styling.
- Never put a control mid-sentence; label then control, with units in the label ("Gap (mm):").
- Page padding comes from `--page-pad` / `--page-pad-x` / `--page-pad-y`; write no padding numbers of your own.
- Every control has a whole-sentence `title`; icon-only or unlabelled controls also need `aria-label` (`ui/src/lib/tooltips.test.ts` fails otherwise).
- No new dependencies, so `just notices` is not needed. If one is added, run it and commit `THIRD-PARTY-NOTICES.md` and `ui/src/generated/third-party.json`.
- Videos cannot go in a collage: only `kind === 'photo'` items are used, with a note for any left out (as Print does).
- Claude builds use a separate cargo target dir (user memory: avoid corrupting the user's `tauri dev` build).

## Scope *(my call)*

In v1: templates, paper sizes (the Print list plus large poster and frame sizes and a custom size), gap, corner rounding, background colour, drag-to-crop, save as PNG/JPEG at a chosen resolution, and a warning when the photos are too small for the size. Out of v1: photomosaic (now #112), printing straight from the tool, ordering from an online print shop (see "Print shops" at the end), zoom within a cell, captions, text, swapping photos between cells by drag.

**Large sizes** *(my call)*: the saved file must be good enough to send to an online print shop for a poster or a framed print, so the page size is not limited to desk-printer paper. Sizes go up to 100 cm on the long side. Resolution is a setting (150, 200 or 300 dpi; default 300 below A2, 150 at A2 and larger, which is what poster shops normally ask for). The file records its dpi (PNG pHYs / JPEG JFIF) so a shop reads the right print size. The longest side is capped at 16,384 pixels, and the tool says so if a choice would exceed it.

## Review Focus

- One photo selected, or fewer photos than the template has cells: unused cells show the background colour; nothing crashes; default template matches the photo count.
- More photos than cells: the extra photos are left out, and the tool says how many ("2 photos left out").
- An unreadable or corrupt photo, or one that has gone missing since the scan: Save stops and names the file; no half-written output remains.
- A rotated (EXIF) phone portrait, and a panorama in a square cell: upright, cropped to fill, focus point honoured.
- A poster-size page (for example 70 x 100 cm at 150 dpi = 4134 x 5906 px): renders without running out of memory, and the file's recorded dpi gives back the physical size.
- Photos with too few pixels for their cell (a small web photo on a 60 x 90 cm poster): the tool shows a "low resolution" warning per cell before saving, with the effective dpi.
- Gap or rounding larger than a cell: cells shrink to nothing safely (clamped), no panic, no negative sizes.
- Cancelling the Save dialog does nothing and shows no error; saving over an existing file keeps the old one if the render fails.

### Task 2: Crop maths and render

**Files:**
- Modify: `crates/pixie-image/src/collage.rs`

**Interfaces:**
- Consumes: `PxRect`, `cell_rects` (Task 1); `crate::decode::decode_scaled(path: &Path, edge: u32) -> Result<DynamicImage>` (upright, longest side at most `edge`).
- Produces:
  - `pub const MAX_SIDE_PX: u32 = 16_384;`
  - `pub fn effective_dpi(src_w: u32, src_h: u32, cell_w_mm: f32, cell_h_mm: f32, focus: (f32, f32)) -> f32`: the pixels the cropped source gives per inch of the printed cell (the crop size comes from `cover_crop`). Tested: a 3000x2000 photo in a 150x100 mm cell is 508 dpi; the same photo in 600x400 mm is 127 dpi.
  - `pub struct CellPhoto { pub path: PathBuf, pub focus_x: f32, pub focus_y: f32 }`
  - `pub struct CollageRequest { pub template_id: String, pub page_w_mm: f32, pub page_h_mm: f32, pub dpi: u32 /* 72..=600 */, pub gap_mm: f32, pub corner_mm: f32, pub background: [u8; 3], pub photos: Vec<Option<CellPhoto>> }` (`photos[i]` fills cell i; `None` leaves it empty)
  - `pub fn cover_crop(src_w: u32, src_h: u32, cell_w: u32, cell_h: u32, focus_x: f32, focus_y: f32) -> (u32, u32, u32, u32)` returning the source rectangle `(x, y, w, h)`: the largest rectangle with the cell's aspect that fits in the source, positioned so `offset = (source_size - crop_size) * focus` per axis, focus clamped to 0..1. This is the same rule as CSS `object-fit: cover; object-position: focus%`.
  - `pub fn render(req: &CollageRequest) -> Result<image::RgbImage>`; the error names the file that could not be read.

- [ ] **Step 1: Write failing tests**: `cover_crop_of_a_wide_photo_in_a_square_cell_keeps_full_height` (400x200 into 100x100, focus 0.5 -> `(100, 0, 200, 200)`; focus 0 -> x 0; focus 1 -> x 200); `cover_crop_of_a_matching_aspect_is_the_whole_photo`; `a_page_larger_than_MAX_SIDE_PX_is_an_error_that_says_so`; `effective_dpi_matches_the_examples`; `a_two_cell_page_has_each_photo_in_its_own_cell` (write a red and a blue jpeg with `pixie_testutil::jpeg`-style helpers or `image` buffers, render `two-across` at 200x100, assert left-centre pixel red and right-centre blue, and the gap column is the background colour); `an_empty_cell_shows_the_background`; `corners_are_rounded_to_the_background` (corner 10 px: the cell's own corner pixel equals the background, its centre does not); `a_photo_that_cannot_be_read_fails_naming_the_file`; `an_unknown_template_id_is_an_error`.
- [ ] **Step 2: Run** `cargo test -p pixie-image collage`. Expected: FAIL.
- [ ] **Step 3: Implement** `cover_crop` and `render`. Convert mm to pixels with `mm / 25.4 * dpi`, rounded, minimum 1; refuse pages over `MAX_SIDE_PX`. To keep memory down on poster sizes, decode and paste one cell at a time (never hold more than the page plus one photo). Decode each photo with `decode_scaled(path, max(cell_w, cell_h))`, crop with `cover_crop`, resize to the cell with `imageops::FilterType::Lanczos3`, and copy into the page. Corner rounding: for each pixel within `corner_px` of a cell corner, skip it if outside the quarter circle (no anti-aliasing needed at print dpi; blend only if easy). Clamp `corner_px` to half the smaller cell side.
- [ ] **Step 4: Run tests.** Expected: PASS. Run `cargo check --workspace --all-targets`; expected: no warnings.

## Print shops (research, not in this plan's tasks)

Checked 2026-11-01 from the vendors' public pages:

- **Prodigi** (api.prodigi.com/v4.0, sandbox at api.sandbox.prodigi.com): REST, `X-API-Key` header, order = recipient address + items with `sku` and `assets[].url`, sizing `fillPrintArea` / `fitPrintArea` / `stretchToPrintArea`, a product endpoint that gives the exact pixel size per SKU, quotes, status webhooks. Sells framed prints, canvas, mounted prints, fine art prints, photo books. Best fit for Pixie.
- **Gelato** (order.gelatoapis.com, `X-API-KEY`): REST with quotes, test orders, webhooks; posters and framed posters in 20+ sizes. Its docs could not be read here (403), so details need checking.
- **Printful**: REST and OAuth, mostly apparel and merchandise, so a weaker fit for framing.
- **Walgreens Photo Prints API**: print-at-store pickup, 2012-era portal, status unknown. Shutterfly, Snapfish, Mpix, Nations Photo Lab and CVS: no current public API found.

**The catch for a desktop app:** Prodigi (and, as far as seen, Gelato) take a *public URL* to the picture, not an upload. Pixie holds local files, so ordering needs somewhere to put the file temporarily (a small Pixie-run upload service, or the user's own cloud drive link via the planned Share by cloud drive tool, #81), and a way to keep the API key out of the app (the user's own key, or a Pixie-run proxy). That is a separate design. This plan only makes sure the saved file has the right size and resolution to send.
